## ما اختُبر فعليًا وما لم يُختبر

- نجح TypeScript، وبناء Vite، والتثبيت النظيف بعد إصلاح lockfile.
- نجحت الاختبارات الأصلية الـ29 مجددًا في jsdom، مع 14 اختبارًا إضافيًا في tests/review.tsx (43 فحصًا ناجحًا إجمالًا). العدد النهائي والنتيجة في ملف السجل؛ المحاكاة ليست اختبار ميكروفون حقيقي أو تشغيل صوت أو اختبارًا بصريًا شاملًا.
- فُحصت CRC للتصدير ولأرشيف المصدر؛ تطابقت بصمات ملفات PDF الـ18؛ رُسمت الصفحات الـ1,233 آليًا دون OCR.
- داخل متصفح Work: فُتحت المعاينة الأصلية، وCode والتصدير، وأُنشئت نسخة مستقلة، ونُقر زر Standard وأُوصل إلى صفحة 108 وظهرت الصفحة الأخيرة بصريًا. كان ذلك فحصًا للنسخة الأصلية؛ ثم فُحصت Standard 108/108 ومساعدة Ankh في نسخة الكود المعدل يوم 17 أكتوبر كما موضح أعلاه.
- تعذرت معاينة الكود المحلي من متصفح Work لأن بيئة المتصفح لا تصل إلى localhost الخاص ببيئة التنفيذ. تنزيل Chromium للاختبارات المحلية فشل بسبب أرشيف تنزيل غير صالح؛ لم يُدَّع اجتياز اختبارات Playwright.
- في المرحلة الأولى يوم16 أكتوبر بقيت نسخة AI Studio المستقلة في Loading code؛ أُرسلت إليها حزمة الإصلاح داخل المنصة، ثم رُفض الطلب لتجاوز الحد الأقصى للتوكنات. لا تُعتبر رسالة مساعد AI Studio وحدها دليل نجاح؛ يلزم فحص الكود/المعاينة أو إعادة تصدير للتحقق.
- توجد ملاحظة build عن حجم JavaScript bundle؛ ليست خطأ بناء. تقسيم الحزمة حسب المسارات تحسين أداء لاحق.

## نقاط متبقية دون ادعاء اكتمال

1. تفعيل المعاينة المعدلة في AI Studio، ثم إعادة تنزيلها ومقارنة الملفات الحرفية. إذا بقيت معلقة فهذه مشكلة تشغيل المنصة، لا سببًا لاستبدال التطبيق الأصلي.
2. اختبار الميكروفون على جهاز المالكة: Voice Mirror → Record my voice → السماح من المتصفح/النظام إن طُلب → نطق جملة → Stop recording → Replay recording → Record again → Delete recording. في preview مضمن قد تمنع سياسة iframe الميكروفون؛ يلزم تجربة تبويب التطبيق الآمن المستقل.
3. مراجعة بصرية للملفات الـ18 داخل العارض الجديد، خصوصًا الخطوط العربية وأحجام الكتب/السلايدز والصفحة الأخيرة، وعلى هاتف وشاشة كبيرة. البصمة تثبت حفظ المحتوى الأصلي، لا رضا المالك عن تصميم الوثيقة نفسها.

## التشغيل والاسترجاع

داخل حزمة التشغيل الكاملة: npm ci، ثم npm run dev. أو npm run build ثم npm run preview. سكربتا predev وprebuild يجهزان worker وخطوط PDF.js من نفس الحزمة المثبتة؛ لا CDN ولا مفتاح API.

عند استرجاع الكود من مستودع kemet-assets الذي يخزن الأصول كأجزاء: شغّل build-assets.py من جذر المستودع، ثم app/restore_work_assets.py، ثم سكربت استعادة review assets المرفق إذا كان موجودًا، وبعدها npm ci داخل app. لا تشغّل workflow النشر. حزمة التشغيل المكتملة لا تحتاج هذه إعادة التجميع.

العودة إلى الحالة السابقة تتم بإبقاء التطبيق الأصلي untouched أو باختيار commit الأصل في فرع المراجعة. لا تستخدم force push أو استبدال main. ملف checkpoint metadata يسجل الأصل والإصدار والأدلة؛ وملفات validation تتضمن النتائج القابلة لإعادة الفحص.
